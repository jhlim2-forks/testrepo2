# 요구사항

## 배경

팀원이 브라우저에서 할 일을 적어 두는 간단한 웹앱이 필요합니다. 첫 버전은 할 일 제목을 입력해 추가하고, 추가한 순서대로 목록을 보는 것까지를 다룹니다. 화면은 한 페이지로 충분하고 한국어로 보여 줍니다. 할 일은 서버 메모리에 보관하므로 서버를 다시 켜면 목록은 비어 있는 상태로 시작합니다.

## 요구사항

- **REQ-01** (구현 예정 #1) 서버는 `/` 요청에 할 일 추가 입력과 할 일 목록이 함께 있는 한국어 한 페이지 화면을 보여 준다.
- **REQ-02** (구현 예정 #1) 사용자가 할 일 제목을 입력해 추가하면 그 할 일이 목록에 담기고, 서버는 추가된 할 일의 식별자와 제목을 돌려준다.
- **REQ-03** (구현 예정 #1) 제목이 비어 있거나 공백 문자만 있으면 추가를 거절하고 목록을 바꾸지 않으며, 한국어 오류 메시지를 돌려준다.
- **REQ-04** (구현 예정 #1) 제목이 200자를 넘으면 추가를 거절하고 목록을 바꾸지 않으며, 한국어 오류 메시지를 돌려준다. 200자까지는 받아들인다.
- **REQ-05** (구현 예정 #1) 할 일 목록은 추가한 순서대로 보여 준다.
- **REQ-06** (구현 예정 #1) 할 일은 서버 메모리에만 보관하므로, 서버를 다시 켜면 목록은 빈 상태에서 시작한다.

## API 계약

모든 API는 `/api/` 아래에서 JSON으로 주고받습니다. 요청과 응답의 문자 인코딩은 UTF-8이며, 응답 헤더는 `Content-Type: application/json; charset=utf-8`입니다.

### `GET /api/todos` — 할 일 목록 조회

- 요청 본문 없음.
- 응답 `200 OK`

  ```json
  { "todos": [ { "id": 1, "title": "회의 자료 준비" }, { "id": 2, "title": "메일 답장" } ] }
  ```

- `todos`는 추가한 순서대로 담은 배열이며, 할 일이 없으면 빈 배열(`[]`)입니다.
- 할 일 하나는 `id`(1부터 1씩 커지는 정수)와 `title`(문자열)로 이루어집니다.

### `POST /api/todos` — 할 일 추가

- 요청 본문

  ```json
  { "title": "회의 자료 준비" }
  ```

- `title`의 앞뒤 공백은 제거한 뒤 저장하며, 길이는 공백을 제거한 제목의 글자 수로 셉니다.
- 응답 `201 Created`

  ```json
  { "id": 1, "title": "회의 자료 준비" }
  ```

- 응답 `400 Bad Request` — 제목이 비었거나 공백뿐인 경우, 제목이 200자를 넘는 경우, 본문이 올바른 JSON이 아닌 경우

  ```json
  { "error": "제목을 입력해 주세요." }
  ```

- `error`는 화면에 그대로 보여 줄 수 있는 한국어 문장입니다.

### 공통

- 위에 적지 않은 메서드로 `/api/todos`를 호출하면 `405 Method Not Allowed`와 `error` 본문을 돌려줍니다.

## 범위 밖

- 완료 표시, 할 일 수정, 할 일 삭제
- 로그인과 사용자 구분, 여러 사용자가 각자의 목록을 갖는 기능
- 데이터베이스 등 서버를 다시 켜도 목록이 남는 저장 방식
- 목록 정렬 변경, 검색, 분류, 페이지 나누기

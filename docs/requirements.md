# 요구사항

## 배경

팀원이 브라우저에서 할 일을 적어 두는 간단한 웹앱이 필요합니다. 첫 버전은 할 일 제목을 입력해 추가하고, 추가한 순서대로 목록을 보는 것까지를 다룹니다. 화면은 한 페이지로 충분하고 한국어로 보여 줍니다. 할 일은 서버 메모리에 보관하므로 서버를 다시 켜면 목록은 비어 있는 상태로 시작합니다.

## 요구사항

- **REQ-01** 서버는 `/` 요청에 할 일 추가 입력과 할 일 목록이 함께 있는 한국어 한 페이지 화면을 보여 준다.
- **REQ-02** 사용자가 할 일 제목을 입력해 추가하면 그 할 일이 목록에 담기고, 서버는 추가된 할 일의 식별자와 제목을 돌려준다.
- **REQ-03** 제목이 비어 있거나 공백 문자만 있으면 추가를 거절하고 목록을 바꾸지 않으며, 한국어 오류 메시지를 돌려준다.
- **REQ-04** 앞뒤 공백을 제거한 제목의 글자 수가 200을 넘으면 추가를 거절하고 목록을 바꾸지 않으며, 한국어 오류 메시지를 돌려준다. 200자까지는 받아들인다. 글자 수는 유니코드 코드 포인트 개수로 센다.
- **REQ-05** 할 일 목록은 추가한 순서대로 보여 준다.
- **REQ-06** 할 일은 서버 메모리에만 보관하므로, 서버를 다시 켜면 목록은 빈 상태에서 시작한다.
- **REQ-07** 할 일이 하나도 없으면 화면의 목록 자리에 안내 문구 `아직 할 일이 없으니 위 입력 칸에서 첫 할 일을 추가해 보세요.`를 보여 준다. 이 문구는 화면에서만 보여 주고 API 응답에는 담지 않는다.
- **REQ-08** 빈 목록 안내 문구는 화면에 있는 할 일 수에 따라서만 보이고 숨는다. 할 일이 하나 이상이면 보여 주지 않고, 추가가 성공해 목록이 비어 있지 않게 되면 화면을 다시 열지 않아도 그 자리에서 문구를 숨기며, 목록이 그대로 비어 있으면 문구를 계속 보여 준다.
- **REQ-09** 할 일을 추가할 때 마감일을 날짜(연-월-일, 시간 없음)로 함께 넣을 수 있고, 넣지 않아도 추가할 수 있다. 마감일을 넣으면 서버는 추가된 할 일의 식별자와 제목과 함께 그 마감일을 돌려주고, 넣지 않으면 지금과 같이 식별자와 제목만 돌려준다.
- **REQ-10** 목록 조회 응답과 화면 목록에서 마감일이 있는 할 일은 제목과 함께 마감일을 보여 주고, 마감일이 없는 할 일은 지금과 같이 제목만 보여 준다.
- **REQ-11** 마감일이 `YYYY-MM-DD` 형식이 아니거나 달력에 없는 날짜(예: `2026-02-30`, 평년의 `2027-02-29`, `2026-13-01`)이면 추가를 거절하고 목록을 바꾸지 않으며, 한국어 오류 메시지를 돌려준다.
- **REQ-12** (구현 예정 #37) 목록의 할 일마다 완료 표시를 하거나 풀 수 있다. 새로 추가한 할 일은 완료하지 않은 상태로 시작하고, 완료 여부는 서버 메모리에 보관하므로 화면을 다시 열어도 유지된다.
- **REQ-13** (구현 예정 #37) 목록 조회 응답과 화면 목록은 완료하지 않은 할 일을 위쪽에, 완료한 할 일을 그 아래쪽에 모아 보여 준다. 두 묶음 안에서는 각각 추가한 순서를 따르며(REQ-05의 추가한 순서는 완료 여부가 같은 할 일끼리 적용한다), 완료한 할 일이 없으면 지금과 같이 추가한 순서대로 보여 준다.
- **REQ-14** (구현 예정 #37) 화면에서 완료한 할 일은 완료하지 않은 할 일보다 흐리게 보여 주고, 목록에서 숨기지 않는다. 빈 목록 안내 문구는 완료 여부와 관계없이 전체 할 일 수로만 보이고 숨는다.
- **REQ-15** (구현 예정 #37) 완료 표시를 바꾸려는 할 일이 없으면 바꾸지 않고 한국어 오류 메시지를 돌려주며, 요청 형식이 올바르지 않으면 완료 여부를 바꾸지 않고 한국어 오류 메시지를 돌려준다.

## API 계약

모든 API는 `/api/` 아래에서 JSON으로 주고받습니다. 요청과 응답의 문자 인코딩은 UTF-8이며, 응답 헤더는 `Content-Type: application/json; charset=utf-8`입니다.

### `GET /api/todos` — 할 일 목록 조회

- 요청 본문 없음.
- 응답 `200 OK`

  ```json
  { "todos": [ { "id": 1, "title": "회의 자료 준비", "due": "2026-10-20" }, { "id": 3, "title": "보고서 제출" }, { "id": 2, "title": "메일 답장", "done": true } ] }
  ```

- `todos`는 완료하지 않은 할 일을 추가한 순서대로 먼저 담고, 그 뒤에 완료한 할 일을 추가한 순서대로 담은 배열입니다. 완료한 할 일이 없으면 추가한 순서 그대로이며, 할 일이 없으면 빈 배열(`[]`)입니다.
- 할 일 하나는 `id`(1부터 1씩 커지는 정수)와 `title`(문자열)로 이루어집니다.
- 마감일이 있는 할 일에는 `due`(`YYYY-MM-DD` 형식의 문자열)가 더 붙습니다. 마감일이 없는 할 일에는 `due` 항목 자체를 넣지 않습니다(`null`이나 빈 문자열로 넣지 않습니다).
- 완료한 할 일에는 `"done": true`가 더 붙습니다. 완료하지 않은 할 일에는 `done` 항목 자체를 넣지 않습니다(`false`나 `null`로 넣지 않습니다).
- 할 일이 없을 때도 응답 형식은 위와 같습니다. 빈 목록 안내 문구는 응답 본문에 담지 않으며, 화면이 `todos`의 길이가 0인지를 보고 직접 보여 줍니다.

### `POST /api/todos` — 할 일 추가

- 요청 본문

  ```json
  { "title": "회의 자료 준비", "due": "2026-10-20" }
  ```

- `due`는 선택 항목입니다. 마감일 없이 추가하려면 `due`를 빼거나, `null` 또는 빈 문자열(`""`)로 보냅니다.
- `due`를 넣을 때는 `YYYY-MM-DD` 형식(연 네 자리, 월 두 자리, 일 두 자리, `-`로 구분)의 문자열이어야 하고, 달력에 실제로 있는 날짜여야 합니다. 윤년의 2월 29일은 받아들이고 평년의 2월 29일은 거절합니다. 앞뒤 공백을 제거하지 않으며, 시간이나 시간대는 받지 않습니다.
- 오늘보다 앞선 날짜도 받아들입니다. 마감일이 지났는지는 판단하지 않습니다.
- 받은 `due` 문자열은 바꾸지 않고 그대로 저장해 돌려줍니다.
- `title`의 앞뒤 공백은 제거한 뒤 저장하며, 길이는 공백을 제거한 제목의 글자 수로 셉니다.
- 글자 수를 세는 기준은 다음과 같습니다.
  - 유니코드 코드 포인트 하나를 1자로 셉니다(Go의 `[]rune` 길이와 같습니다). 바이트 수로 세지 않습니다.
  - 결합 문자나 이모지 조합처럼 화면에 한 글자처럼 보이는 경우에도 코드 포인트마다 1자로 셉니다. 즉 사용자가 눈으로 인식하는 글자 수를 따르지 않습니다.
    - 예: `한`(U+D55C)은 1자, `가`를 `ᄀ`+`ᅡ`(U+1100 U+1161)로 적으면 2자, `é`를 `e`+`◌́`(U+0065 U+0301)로 적으면 2자, `👍🏻`(U+1F44D U+1F3FB)은 2자입니다.
  - 제목 안쪽(앞뒤가 아닌 중간)의 공백은 제거하지 않고 1자로 셉니다.
- 응답 `201 Created`

  ```json
  { "id": 1, "title": "회의 자료 준비", "due": "2026-10-20" }
  ```

  마감일 없이 추가하면 `due` 항목 없이 `{ "id": 1, "title": "회의 자료 준비" }`를 돌려줍니다.

- 응답 `400 Bad Request` — 아래 경우에 각각 정해진 `error` 문장을 돌려줍니다. 본문 형태는 모두 `{ "error": "..." }` 한 가지입니다.

  | 경우 | `error` 문장 |
  | --- | --- |
  | 본문이 올바른 JSON이 아니거나, 본문이 비어 있거나, `title`이 문자열이 아니거나, `due`가 문자열과 `null`이 아닌 값인 경우 | `요청 형식이 올바르지 않습니다.` |
  | `title`이 없거나, 비었거나, 공백 문자만 있는 경우 | `제목을 입력해 주세요.` |
  | 공백을 제거한 제목이 200자를 넘는 경우 | `제목은 200자까지 입력할 수 있습니다.` |
  | `due`가 빈 문자열이 아닌데 `YYYY-MM-DD` 형식이 아니거나 달력에 없는 날짜인 경우 | `마감일은 실제 있는 날짜를 YYYY-MM-DD 형식으로 입력해 주세요.` |

  ```json
  { "error": "요청 형식이 올바르지 않습니다." }
  ```

- 여러 경우에 함께 해당하면 위 표의 순서대로 먼저 걸리는 문장 하나만 돌려줍니다.
- `error`는 화면에 그대로 보여 줄 수 있는 한국어 문장입니다.
- 새로 추가한 할 일은 완료하지 않은 상태이므로 응답에 `done` 항목이 없습니다. 요청 본문에 `done`이 있어도 무시합니다.

### `PATCH /api/todos/{id}` — 완료 표시 바꾸기

- `{id}`는 바꿀 할 일의 `id`입니다(예: `/api/todos/2`).
- 요청 본문

  ```json
  { "done": true }
  ```

- `done`은 꼭 있어야 하는 불리언 값입니다. `true`면 완료 표시를 하고, `false`면 완료 표시를 풉니다. 이미 같은 상태이면 바꾸지 않고 성공으로 응답합니다.
- `done` 밖의 항목은 무시하며, 제목과 마감일은 바꾸지 않습니다.
- 응답 `200 OK` — 바꾼 뒤의 할 일 하나를 목록 조회와 같은 형태로 돌려줍니다.

  ```json
  { "id": 2, "title": "메일 답장", "done": true }
  ```

  완료 표시를 풀면 `done` 항목 없이 `{ "id": 2, "title": "메일 답장" }`를 돌려줍니다.

- 실패 응답 — 아래 경우에 각각 정해진 상태와 `error` 문장을 돌려주며, 완료 여부는 바뀌지 않습니다. 본문 형태는 모두 `{ "error": "..." }` 한 가지입니다.

  | 경우 | 상태 | `error` 문장 |
  | --- | --- | --- |
  | `{id}`가 1 이상의 정수가 아니거나, 그 `id`의 할 일이 없는 경우 | `404 Not Found` | `할 일을 찾을 수 없습니다.` |
  | 본문이 올바른 JSON이 아니거나, 본문이 비어 있거나, `done`이 없거나, `done`이 불리언이 아닌 경우(`null`, `"true"`, `1` 등) | `400 Bad Request` | `요청 형식이 올바르지 않습니다.` |

- 여러 경우에 함께 해당하면 위 표의 순서대로 먼저 걸리는 문장 하나만 돌려줍니다.

### 공통

- 위에 적지 않은 메서드로 `/api/todos`나 `/api/todos/{id}`를 호출하면 `405 Method Not Allowed`와 `{ "error": "지원하지 않는 요청 방식입니다." }`를 돌려줍니다.

## 범위 밖

- 할 일 수정, 할 일 삭제
- 완료한 할 일을 목록에서 숨기거나 따로 모아 보기, 완료한 할 일을 한꺼번에 지우기, 완료한 시각 기록
- 로그인과 사용자 구분, 여러 사용자가 각자의 목록을 갖는 기능
- 데이터베이스 등 서버를 다시 켜도 목록이 남는 저장 방식
- 목록 정렬 변경, 검색, 분류, 페이지 나누기(REQ-13의 완료한 할 일을 아래쪽에 모으는 것은 제외)
- 화면 디자인 전반 변경(배치, 색, 글꼴 등)
- 할 일 추가와 목록 조회의 동작 및 API 응답 형식 변경(REQ-09~REQ-11의 마감일, REQ-12~REQ-15의 완료 표시는 제외)
- 마감일이 지난 할 일을 따로 표시하거나 알려 주는 기능
- 마감일 순 정렬
- 마감일에 시간이나 시간대를 함께 정하는 기능, 이미 추가한 할 일의 마감일 수정과 삭제
- 빈 목록 안내 문구를 서버 응답에 담아 내려 주는 방식, 문구의 다국어 지원이나 사용자별 변경

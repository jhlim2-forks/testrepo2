# 설계

## 구조

- 저장소 루트의 단일 Go 모듈(`module todo`)로 두고, Go 표준 라이브러리와 HTML/CSS/JavaScript만 사용합니다.
- 서버는 `go run .`으로 실행하며 `-listen` 플래그(기본값 `127.0.0.1:8091`)로 주소를 받습니다.
- 서버는 두 가지 일을 합니다.
  - `/` 요청에 `index.html` 한 파일을 제공합니다.
  - `/api/todos`에서 할 일 목록 조회와 추가를, `/api/todos/{id}`에서 완료 표시 바꾸기와 제목 고치기(REQ-16~REQ-18)를 JSON으로 처리합니다.
- 할 일은 서버 메모리의 목록 하나에 추가한 순서대로 담습니다. 식별자는 1부터 시작해 추가할 때마다 1씩 커지는 정수입니다.
- 할 일은 식별자, 제목, 마감일(선택)을 가집니다. 마감일은 받은 `YYYY-MM-DD` 문자열 그대로 보관하며, 마감일이 없으면 JSON에 `due` 항목을 넣지 않습니다(Go라면 `omitempty`). 마감일은 날짜 글자로만 다루고 시간대 변환을 하지 않습니다.
- 할 일은 완료 여부(불리언, 처음에는 완료하지 않음)도 가집니다. 완료하지 않은 할 일은 JSON에 `done` 항목을 넣지 않습니다(Go라면 `omitempty`).
- 서버 메모리의 목록은 계속 추가한 순서로 보관합니다. 목록 조회 응답을 만들 때만 완료하지 않은 할 일을 먼저, 완료한 할 일을 뒤에 담으며 각 묶음 안의 추가 순서는 유지합니다(Go라면 복사본에 `sort.SliceStable`). 완료 표시를 바꾸거나 제목을 고쳐도 보관 순서와 식별자는 바뀌지 않습니다.
- 목록은 여러 요청이 동시에 들어와도 안전하도록 잠금으로 보호합니다.
- 저장소가 메모리이므로 서버 프로세스가 끝나면 목록도 함께 사라집니다.

## API

`docs/requirements.md`의 `## API 계약`에 적은 계약을 그대로 따릅니다.

| 메서드와 경로 | 하는 일 | 성공 응답 | 실패 응답 |
| --- | --- | --- | --- |
| `GET /` | 한 페이지 화면 제공 | `200` + HTML | — |
| `GET /api/todos` | 할 일 목록을 돌려줌. 완료하지 않은 할 일을 먼저, 완료한 할 일을 뒤에 두며 각 묶음 안은 추가한 순서 | `200` + `{"todos":[...]}` | — |
| `POST /api/todos` | 할 일 추가 | `201` + `{"id":1,"title":"..."}` (마감일이 있으면 `"due":"YYYY-MM-DD"`가 더 붙음) | `400` + `{"error":"..."}` |
| `PATCH /api/todos/{id}` | 할 일의 완료 표시를 하거나 풂, 제목을 고침 | `200` + `{"id":2,"title":"...","done":true}` (완료 표시를 풀면 `done` 없음) | `404` 또는 `400` + `{"error":"..."}` |
| 그 밖의 메서드로 `/api/todos`, `/api/todos/{id}` | 처리하지 않음 | — | `405` + `{"error":"..."}` |

제목 검사 순서는 다음과 같습니다.

1. 요청 본문을 JSON으로 읽습니다. 읽을 수 없거나 본문이 비어 있거나 `title`이 문자열이 아니거나 `due`가 문자열과 `null`이 아닌 값이면 `400`이며 메시지는 `요청 형식이 올바르지 않습니다.`입니다.
2. `title`의 앞뒤 공백을 제거합니다.
3. 결과가 빈 문자열이면 `400`이며 메시지는 `제목을 입력해 주세요.`입니다. `title` 항목이 아예 없는 경우도 빈 문자열로 봅니다.
4. 결과의 글자 수가 200자를 넘으면 `400`이며 메시지는 `제목은 200자까지 입력할 수 있습니다.`입니다. 글자 수는 유니코드 코드 포인트 개수(Go의 `[]rune` 길이)로 세며, 결합 문자나 이모지 조합도 코드 포인트마다 1자로 셉니다.
5. `due`가 없거나 `null`이거나 빈 문자열이면 마감일 없는 할 일로 봅니다. 그 밖의 문자열은 `YYYY-MM-DD` 형식(정확히 10자, 숫자 4-2-2와 `-`)이고 달력에 있는 날짜인지 확인합니다(Go라면 형식 확인 뒤 `time.Parse("2006-01-02", due)`로 날짜를 검사합니다). 아니면 `400`이며 메시지는 `마감일은 실제 있는 날짜를 YYYY-MM-DD 형식으로 입력해 주세요.`입니다.
6. 모두 통과하면 목록 끝에 완료하지 않은 할 일로 추가하고 `201`로 추가 결과를 돌려줍니다.

완료 표시 바꾸기와 제목 고치기(`PATCH /api/todos/{id}`)의 검사 순서는 다음과 같습니다.

1. 경로의 `{id}`를 10진 정수로 읽습니다. 읽을 수 없거나 1보다 작거나 그 `id`의 할 일이 없으면 `404`이며 메시지는 `할 일을 찾을 수 없습니다.`입니다.
2. 요청 본문을 JSON으로 읽습니다. 읽을 수 없거나 본문이 비어 있거나 `done`과 `title`이 모두 없거나, `done`이 있는데 불리언이 아니거나, `title`이 있는데 문자열이 아니면(`null` 포함) `400`이며 메시지는 `요청 형식이 올바르지 않습니다.`입니다.
3. `title`이 있으면 앞뒤 공백을 제거합니다. 결과가 빈 문자열이면 `400`이며 메시지는 `제목을 입력해 주세요.`입니다.
4. 3의 결과의 글자 수가 200자를 넘으면 `400`이며 메시지는 `제목은 200자까지 입력할 수 있습니다.`입니다. 글자 수는 추가할 때와 같이 유니코드 코드 포인트 개수(Go의 `[]rune` 길이)로 셉니다. 제목 검사는 추가(`POST /api/todos`)와 같은 함수를 함께 써서 두 규칙이 어긋나지 않게 합니다.
5. 모든 검사를 통과한 뒤에만 잠금 안에서 그 할 일의 완료 여부를 `done` 값으로, 제목을 3에서 공백을 제거한 값으로 바꿉니다(본문에 있는 항목만). 검사 중 하나라도 실패하면 아무것도 바꾸지 않습니다. `200`으로 바꾼 뒤의 할 일을 돌려줍니다. 이미 같은 값이면 그대로 `200`입니다.

실패 응답 본문은 모두 `{"error":"..."}` 한 가지 형태이며, 문장은 `docs/requirements.md`의 `## API 계약`에 적은 다섯 가지(추가의 네 가지와 완료 표시의 `할 일을 찾을 수 없습니다.`, 그리고 `405`의 `지원하지 않는 요청 방식입니다.`)만 사용합니다. 제목 고치기는 새 문장을 만들지 않고 추가와 같은 `제목을 입력해 주세요.`, `제목은 200자까지 입력할 수 있습니다.`를 씁니다. UI는 이 문장을 그대로 보여 줍니다.

## UI

`index.html` 한 파일로 만듭니다. 모든 문구는 한국어입니다.

- 머리글: `할 일 목록`
- 추가 영역: 제목 입력 칸(안내 문구 `할 일을 입력하세요`), 마감일 입력 칸, `추가` 버튼
  - 마감일 입력 칸은 날짜 선택 칸(`<input type="date" id="due">`)이고 이름표는 `마감일(선택)`입니다. 비워 두면 마감일 없이 추가합니다.
  - `추가`를 누르면 마감일 입력 칸의 값(`YYYY-MM-DD` 또는 빈 문자열)을 `due`로 함께 보냅니다. 추가가 성공하면 제목과 함께 마감일 입력 칸도 비웁니다.
- 남은 할 일 개수 영역: 추가 영역과 목록 영역 사이(목록 영역 바로 위)에 문단 요소 하나(`id="remaining-count"`)를 두고 `남은 할 일 N개`를 글자로 보여 줍니다. `N`은 받아 온 `todos` 중 `done`이 `true`가 아닌 할 일의 수입니다(아라비아 숫자, 천 단위 구분 없음). 기본 상태는 `hidden`이며, 목록을 그릴 때마다 받아 온 할 일 수가 0이면 `hidden`으로 숨기고(이때는 빈 목록 안내 영역만 보입니다) 1 이상이면 `hidden`을 풀어 보여 줍니다. 할 일이 있지만 모두 완료했으면 숨기지 않고 `남은 할 일 0개`를 보여 줍니다. 개수는 화면에서 세며 API 응답 형식은 바꾸지 않습니다.
- 목록 영역: 서버가 돌려준 `todos` 순서 그대로 위에서 아래로 나열합니다. 그래서 완료하지 않은 할 일이 추가한 순서대로 먼저 보이고, 완료한 할 일이 그 아래에 추가한 순서대로 보입니다.
  - 마감일이 있는 할 일은 제목 뒤에 `마감 2026-10-20`처럼 `마감`과 받은 날짜를 그대로 붙여 보여 줍니다(예: `회의 자료 준비 · 마감 2026-10-20`). 마감일이 없는 할 일은 지금과 같이 제목만 보여 줍니다.
  - 제목과 마감일은 모두 글자로만 넣습니다.
  - 각 줄의 제목 앞에 완료 표시용 체크박스(`<input type="checkbox">`, 이름표 `완료`)를 둡니다. 완료한 할 일은 체크된 상태로 그립니다.
  - 체크박스를 바꾸면 `PATCH /api/todos/{id}`에 `{"done": 체크 여부}`를 보내고, 끝나면 `GET /api/todos`로 목록을 다시 받아 그립니다. 그래서 완료한 할 일은 그 자리에서 목록 아래쪽으로 옮겨지고, 완료를 풀면 완료하지 않은 할 일 묶음의 추가 순서 자리로 돌아갑니다. 실패하면 서버가 준 `error` 문장을 오류 영역에 보여 주고 목록을 다시 받아 그립니다.
  - (REQ-16~REQ-18) 각 줄의 제목 뒤에 `수정` 버튼을 둡니다. 누르면 그 줄의 제목 글자 자리에 지금 제목이 채워진 입력 칸과 `저장`, `취소` 버튼이 나타납니다. 한 번에 한 줄만 고칠 수 있으며, 다른 줄의 `수정`을 누르면 앞서 고치던 줄은 저장하지 않고 닫습니다.
    - `저장`을 누르거나 입력 칸에서 Enter를 누르면 `PATCH /api/todos/{id}`에 `{"title": 입력값}`을 보냅니다. 성공하면 고치기를 닫고 `GET /api/todos`로 목록을 다시 받아 그립니다.
    - 거절되면 서버가 준 `error` 문장을 오류 영역에 보여 주고, 고치던 입력 칸과 입력한 글자는 그대로 둡니다.
    - `취소`를 누르거나 입력 칸에서 Esc를 누르면 서버에 보내지 않고 원래 제목으로 돌아갑니다.
    - 마감일과 완료 체크박스는 고치는 동안에도 그대로 보여 주며, 고친 제목도 글자로만 넣습니다.
  - 완료한 할 일의 줄은 `done` 클래스를 붙여 흐리게(예: `opacity: .5`) 보여 줍니다. 글자 내용(제목, 마감일)은 바꾸지 않고 숨기지도 않습니다. 화면의 줄 순서는 서버가 돌려준 `todos` 순서를 그대로 따릅니다.
- 빈 목록 안내 영역: 목록 자리(목록 영역 바로 아래)에 할 일 항목과 분리된 문단 요소 하나(`id="empty-message"`)를 마크업으로 두고, 그 안에 `아직 할 일이 없으니 위 입력 칸에서 첫 할 일을 추가해 보세요.`를 글자로 적어 둡니다. 기본 상태는 `hidden`이며, 목록을 그릴 때마다 받아 온 할 일 수가 0이면 `hidden`을 풀어 보여 주고 1 이상이면 다시 `hidden`으로 숨깁니다. 문구는 `index.html`에만 두고 API 응답에서 받아 오지 않습니다.
- 오류 영역: 추가나 완료 표시 바꾸기, 제목 고치기가 거절되면 서버가 준 `error` 문장을 입력 칸 아래에 보여 줍니다. 이 중 하나를 새로 요청할 때마다 먼저 오류 영역을 비우므로, 다음 요청이 성공하면 오류 문장은 남지 않고, 다시 거절되면 그 요청의 문장으로 바뀝니다. 빈 목록 안내 영역은 오류 여부가 아니라 받아 온 할 일 수만 보고 표시 여부를 정합니다.
- 동작: 화면을 열면 `GET /api/todos`로 목록을 받아 그립니다. `추가` 버튼을 누르거나 입력 칸에서 Enter를 누르면 `POST /api/todos`를 호출하고, 성공하면 입력 칸을 비우고 `GET /api/todos`로 목록을 다시 받아 그립니다. 새 할 일은 완료하지 않은 할 일 묶음의 끝, 완료한 할 일보다 위에 보입니다. 목록을 그리는 함수 하나가 항목 나열, 빈 목록 안내 영역의 표시 여부, 남은 할 일 개수와 그 영역의 표시 여부를 함께 정하므로, 첫 할 일을 추가하면 화면을 다시 열지 않아도 안내 문구가 사라지고 남은 할 일 개수가 나타나며, 할 일을 추가하거나 완료 표시를 바꾸면 남은 할 일 개수도 그 자리에서 바뀝니다.

## 수용 기준

- **REQ-01** `GET /`가 `200`과 HTML을 돌려주고, 그 화면에 제목 입력 칸과 `추가` 버튼, 할 일 목록 영역이 한국어로 들어 있다.
- **REQ-02** `POST /api/todos`에 `{"title":"회의 자료 준비"}`를 보내면 `201`과 `{"id":1,"title":"회의 자료 준비"}`를 돌려주고, 이어서 `GET /api/todos`를 호출하면 그 할 일이 목록에 들어 있다. 본문이 올바른 JSON이 아닌 경우(예: `{"title":`)와 `title`이 문자열이 아닌 경우(예: `{"title":123}`)에는 `400`과 `{"error":"요청 형식이 올바르지 않습니다."}`를 돌려주고 `GET /api/todos`의 목록 길이가 호출 전과 같다.
- **REQ-03** `POST /api/todos`에 `{"title":""}`, `{"title":"   "}`, `{}`를 보내면 각각 `400`과 `{"error":"제목을 입력해 주세요."}`를 돌려주고, `GET /api/todos`의 목록 길이가 호출 전과 같다.
- **REQ-04** 앞뒤 공백을 제거한 제목의 코드 포인트 수가 200일 때는 `201`로 추가되고, 201일 때는 `400`과 `{"error":"제목은 200자까지 입력할 수 있습니다."}`를 돌려주며 `GET /api/todos`의 목록 길이가 호출 전과 같다. 다음 사례로 계산 기준을 확인한다.
  - 한글 `가` 200번 반복(600바이트)은 `201`, 201번 반복은 `400`이다. 즉 바이트 수로 세지 않는다.
  - 앞뒤에 공백을 붙인 `" " + 한글 200자 + " "`는 `201`이고, 저장된 `title`에는 앞뒤 공백이 없다.
  - `e`+`◌́`(U+0065 U+0301) 쌍을 100번 반복한 제목은 코드 포인트 200개이므로 `201`이고, 101번 반복(코드 포인트 202개)은 `400`이다. 즉 눈에 보이는 글자 수가 아니라 코드 포인트 수로 센다.
- **REQ-05** 할 일 세 건을 차례로 추가한 뒤 `GET /api/todos`를 호출하면 `todos` 배열의 제목이 추가한 순서와 같다.
- **REQ-06** 새로 만든 서버에 `GET /api/todos`를 호출하면 `todos`가 빈 배열이다.
- **REQ-07** `GET /`가 돌려주는 HTML에 `id="empty-message"` 요소가 있고, 그 요소에 `아직 할 일이 없으니 위 입력 칸에서 첫 할 일을 추가해 보세요.` 문구가 그대로 들어 있다. 할 일이 없는 서버에 `GET /api/todos`를 호출하면 `todos`는 빈 배열이고 응답 본문에 이 문구가 들어 있지 않다.
- **REQ-08** 브라우저에서 아래 절차를 그대로 따라가 화면에 보이는 것으로 확인한다.

- **REQ-12** 할 일 하나를 추가한 뒤 `PATCH /api/todos/1`에 `{"done":true}`를 보내면 `200`과 `{"id":1,"title":"회의 자료 준비","done":true}`를 돌려주고, 이어서 `GET /api/todos`의 그 할 일에 `"done":true`가 있다. 다시 `{"done":false}`를 보내면 `200`과 `done` 항목 없는 `{"id":1,"title":"회의 자료 준비"}`를 돌려주고 목록에서도 `done` 항목이 없다. 같은 값(`{"done":true}`)을 두 번 보내도 두 번 모두 `200`이다. 새로 추가한 할 일의 `POST` 응답과 목록 항목에는 `done` 항목이 없다. 마감일이 있는 할 일의 완료 표시를 바꿔도 `title`과 `due`는 그대로다.
- **REQ-13** `가`, `나`, `다`를 차례로 추가하고 `가`(id 1)를 완료 표시하면 `GET /api/todos`의 `todos`가 `[{"id":2,"title":"나"},{"id":3,"title":"다"},{"id":1,"title":"가","done":true}]` 순서다. 이어서 `나`(id 2)도 완료 표시하면 `다`, `가`, `나` 순서(완료 묶음 안은 추가 순서)이고, `가`의 완료 표시를 풀면 `가`, `다`, `나` 순서다. 완료한 할 일이 없을 때는 추가한 순서 그대로다. 브라우저에서 체크박스를 누르면 화면을 다시 열지 않아도 그 줄이 목록 아래쪽으로 옮겨진다.
- **REQ-14** `GET /`가 돌려주는 HTML에 완료한 할 일 줄을 흐리게 보여 주는 `done` 클래스의 스타일이 있다. 브라우저에서 아래 절차로 확인한다.
  1. 할 일 두 건을 추가하고 첫 번째 줄의 체크박스를 누르면, 그 줄이 목록 아래쪽에서 체크된 채로 흐리게 보이고 제목과 마감일 글자는 그대로 보인다. 완료한 줄은 목록에서 사라지지 않는다.
  2. 화면을 새로 고쳐도 1번의 보임새가 그대로 다시 나타난다.
  3. 할 일이 한 건뿐일 때 그 할 일을 완료 표시해도 빈 목록 안내 문구는 보이지 않는다.
- **REQ-15** `PATCH /api/todos/99`(없는 `id`), `PATCH /api/todos/0`, `PATCH /api/todos/abc`는 각각 `404`와 `{"error":"할 일을 찾을 수 없습니다."}`를 돌려준다. 있는 할 일에 본문 `{"done":`(올바르지 않은 JSON), 빈 본문, `{}`, `{"done":null}`, `{"done":"true"}`, `{"done":1}`을 보내면 각각 `400`과 `{"error":"요청 형식이 올바르지 않습니다."}`를 돌려주고 `GET /api/todos`의 그 할 일의 완료 여부가 호출 전과 같다. 없는 `id`에 올바르지 않은 본문을 보내면 표의 순서대로 `404`이다. `GET /api/todos/1`이나 `DELETE /api/todos/1`은 `405`와 `{"error":"지원하지 않는 요청 방식입니다."}`를 돌려준다.
- **REQ-16** `회의 자료 준비`(마감일 `2026-10-20`)와 `메일 답장`을 차례로 추가하고 `메일 답장`(id 2)을 완료 표시한 뒤, `PATCH /api/todos/1`에 `{"title":"  회의 자료 다시 준비  "}`를 보내면 `200`과 `{"id":1,"title":"회의 자료 다시 준비","due":"2026-10-20"}`를 돌려준다. 이어서 `GET /api/todos`의 `todos`가 `[{"id":1,"title":"회의 자료 다시 준비","due":"2026-10-20"},{"id":2,"title":"메일 답장","done":true}]`이다. `PATCH /api/todos/2`에 `{"title":"메일 다시 답장"}`을 보내면 `200`과 `{"id":2,"title":"메일 다시 답장","done":true}`를 돌려준다(완료 여부 유지). 지금 제목과 같은 제목을 보내도 `200`이다. `{"done":false,"title":"메일 답장"}`을 보내면 완료 표시를 풀고 제목도 바꾼 `{"id":2,"title":"메일 답장"}`을 돌려준다. 브라우저에서 줄의 `수정`을 눌러 제목을 고치고 `저장`하면 화면을 다시 열지 않아도 그 줄에 고친 제목이 같은 자리에 보이고, 화면을 새로 고쳐도 그대로이며, `취소`하면 원래 제목이 그대로 보인다.
- **REQ-17** 할 일 하나(`회의 자료 준비`)를 추가한 뒤 `PATCH /api/todos/1`에 `{"title":""}`, `{"title":"   "}`를 보내면 각각 `400`과 `{"error":"제목을 입력해 주세요."}`를 돌려주고, 한글 `가` 201번 반복은 `400`과 `{"error":"제목은 200자까지 입력할 수 있습니다."}`를 돌려준다. 세 경우 모두 `GET /api/todos`의 그 할 일 제목은 `회의 자료 준비` 그대로다. 한글 `가` 200번 반복과 `" " + 한글 200자 + " "`는 `200`이고 저장된 제목은 앞뒤 공백 없이 200자다. `e`+`◌́`(U+0065 U+0301) 쌍 100번 반복은 `200`, 101번 반복은 `400`이다. `{"done":true,"title":""}`는 `400`과 `제목을 입력해 주세요.`를 돌려주고 완료 여부도 바뀌지 않는다. 브라우저에서 빈 제목으로 `저장`하면 오류 영역에 `제목을 입력해 주세요.`가 보이고 입력 칸이 열린 채로 남는다.

- **REQ-19** (구현 예정) `GET /`가 돌려주는 HTML에 `id="remaining-count"` 요소가 목록 영역보다 앞에 있고, 할 일이 없는 서버에 `GET /api/todos`를 호출하면 응답 본문에 `남은 할 일`이 들어 있지 않으며 응답 형식은 그대로다. 브라우저에서 아래 절차로 확인한다.
  1. 할 일이 없는 서버를 켜고 `/`를 열면 빈 목록 안내 문구만 보이고 `남은 할 일` 문구는 보이지 않는다.
  2. `가`, `나`, `다`를 차례로 추가하면 화면을 다시 열지 않아도 첫 추가 때 `남은 할 일 1개`가 나타나고, 추가할 때마다 `2개`, `3개`로 바뀐다.
  3. `가`의 체크박스를 누르면 `남은 할 일 2개`, 다시 풀면 `남은 할 일 3개`가 된다. 세 건을 모두 완료 표시하면 개수 문구가 숨지 않고 `남은 할 일 0개`가 된다.
  4. 빈 제목으로 `추가`를 눌러 거절되면 개수는 바뀌지 않는다.
  5. 화면을 새로 고치면 그때의 완료하지 않은 할 일 수가 그대로 다시 보인다.

## 위험

- 메모리 저장이므로 서버를 다시 켜면 입력한 할 일이 사라집니다. 첫 버전에서 받아들이는 제약이며, 화면에도 데이터가 유지된다는 기대를 주는 문구를 두지 않습니다.
- 200자 한도를 바이트 수로 세면 한글 제목이 70자 정도에서 막힙니다. 유니코드 코드 포인트 수로 세어 이를 피합니다. 결합 문자나 이모지 조합은 보이는 것보다 많은 글자로 세지지만, 표준 라이브러리만으로 사용자 인식 글자 수를 세기는 어려워 첫 버전에서는 코드 포인트 기준으로 둡니다.
- 입력한 제목을 화면에 그릴 때 HTML로 해석하면 의도하지 않은 내용이 실행될 수 있습니다. 제목은 항상 글자로만 넣습니다.
- 여러 탭에서 동시에 추가하면 한 탭의 화면이 오래된 목록을 보여 줄 수 있습니다. 첫 버전은 화면을 다시 열어 맞추는 수준으로 둡니다.
- 빈 목록 안내 문구를 화면과 서버 응답 두 곳에서 관리하면 문구가 서로 어긋날 수 있습니다. 문구는 `index.html` 한 곳에만 두고 API 응답 형식은 그대로 둡니다.
- 화면에서 안내 문구가 보이고 숨는 동작은 표준 라이브러리 테스트만으로는 브라우저와 똑같이 재현할 수 없습니다. 자동 검사로는 화면 파일에 담긴 문구와 서버 응답까지만 확인하고, 실제 보임새는 수용 기준의 재현 절차를 따라가 확인합니다.
- 안내 문구를 목록 항목과 같은 방식으로 그리면 할 일이 하나도 없는 상태를 할 일 한 건처럼 보여 줄 수 있습니다. 항목 나열과 분리된 요소 하나에 담아 이를 피합니다.
- 마감일을 시각으로 바꿔 다루면 서버나 브라우저의 시간대에 따라 날짜가 하루 밀릴 수 있습니다. 마감일은 `YYYY-MM-DD` 글자 그대로 받고 저장하고 보여 주며, 날짜 객체로 바꾸는 것은 서버의 날짜 검사에만 씁니다.
- 날짜 선택 칸의 모양과 입력 방식은 브라우저마다 다릅니다. 어떤 브라우저든 서버가 형식과 날짜를 다시 검사하므로 잘못된 값은 저장되지 않습니다.
- 마감일이 없는 할 일의 응답 형식을 지금과 같게(`due` 항목 없음) 두어, 마감일을 쓰지 않는 기존 동작과 기존 테스트가 그대로 성립하게 합니다.
- 완료한 할 일을 아래쪽에 모으는 일을 화면과 서버가 따로 하면 순서가 서로 어긋날 수 있습니다. 순서는 서버의 목록 조회 응답 한 곳에서 정하고 화면은 받은 순서를 그대로 그립니다.
- 체크박스를 누르자마자 줄이 아래쪽으로 옮겨지므로, 사용자가 잘못 누른 줄을 찾기 어려울 수 있습니다. 완료한 줄도 숨기지 않고 체크박스로 바로 풀 수 있게 해 되돌릴 수 있도록 합니다.
- 여러 탭에서 같은 할 일의 완료 표시를 바꾸면 마지막 요청의 값이 남습니다. 요청은 뒤집기가 아니라 `done` 값을 정해 보내므로, 같은 요청이 두 번 가도 결과가 같습니다.
- 제목 고치기를 추가와 다른 곳에서 따로 검사하면 두 규칙이 어긋나 추가할 때는 거절되는 제목이 고칠 때는 받아들여질 수 있습니다. 서버의 제목 검사는 추가와 고치기가 같은 함수를 함께 쓰고, 수용 기준도 추가와 같은 사례(빈 제목, 공백만, 200자 경계, 결합 문자)로 확인합니다.
- 여러 탭에서 같은 할 일의 제목을 고치면 마지막으로 저장한 제목이 남고, 다른 탭의 화면은 다시 열 때까지 옛 제목을 보여 줄 수 있습니다. 첫 버전은 추가와 같이 화면을 다시 열어 맞추는 수준으로 둡니다.
- 흐리게 보이는 줄은 글자 대비가 낮아 읽기 어려울 수 있습니다. 글자는 그대로 두고 흐림 정도만 조절하며, 체크박스 상태로도 완료 여부를 알 수 있게 합니다.
- 남은 할 일 개수를 화면과 서버가 따로 세면 서로 어긋날 수 있습니다. 개수는 화면이 목록을 그릴 때 받아 온 `todos`로만 세고, API 응답 형식은 바꾸지 않습니다.
